# UI / 화면 표현

`cprog`가 터미널에 **어떻게** 그리는지, 상태별 예제와 함께 정의한다. 렌더러는 이 문서를
기준으로 구현·테스트된다.

> 예제는 ASCII 목업이다. 실제로는 블록 글리프와 색을 쓰지만, 필드 순서와 형태는 아래가
> 규격이다.

## 2영역 화면 모델

`cprog`는 전체 화면을 뺏지 않는다(alternate screen 안 씀). `cp` 출력은 평소처럼 스크롤되고,
필요할 때만 하단에 **footer**를 고정한다.

footer는 **항상 두 줄**이고, 느린 파일일 때만 나타난다.

**사용자가 `-v`를 준 경우** — cp 출력을 그대로 중계하고, footer 첫 줄은 비운다:

```
┌ 터미널 ─────────────────────────────────────────────┐
│ 'a.iso' -> '/mnt/backup/a.iso'                       │  ← 로그 영역
│ 'b.iso' -> '/mnt/backup/b.iso'                       │     (cp 출력을 그대로 중계)
│                                                      │  ← footer 1행: 빈 줄(구분)
│  ████████████░░░░░░░░  62.33 %  0.9/1.4 GiB  ⏳ 00:05│  ← footer 2행: 진행바
└──────────────────────────────────────────────────────┘
```

**`-v`를 주지 않은 경우** — 중계하지 않고(‑ `cp`처럼 조용하다), footer 첫 줄이 파일을 알려준다:

```
┌ 터미널 ─────────────────────────────────────────────┐
│ $ cp -r archives /mnt/data/backup                    │  ← 로그 영역(조용함)
│                                                      │
│ …/archives/dataset.tar.zst                           │  ← footer 1행: 대상 경로
│  ████████████░░░░░░░░  62.33 %  0.9/1.4 GiB  ⏳ 00:05│  ← footer 2행: 진행바
└──────────────────────────────────────────────────────┘
```

- **로그 영역(위):** `cp`가 낸 것을 그대로 흘려준다. `cprog`가 내용을 고치지 않는다.
  - **`-v`를 준 경우에만 중계한다.** 사용자가 요청하지 않은 출력을 스크롤백에 쏟지 않는다 —
    쏟으면 그 지점 하나가 순정 `cp`와 눈에 보이게 달라진다
    ([`capture-and-verbose.md`](./capture-and-verbose.md)).
  - `cp`의 **에러(stderr)는 `-v` 유무와 무관하게 항상** 중계한다. 그건 사용자가 봐야 할 것이고
    `cp`도 냈을 것이다.
- **footer(아래):** `cprog`가 그리는 **2줄**. **오직 현재 파일이 느릴 때만** 나타나고, 그 파일이
  끝나면 사라진다. footer에는 **cp 로그가 절대 안 들어간다.**
  - **1행** — `-v`가 없으면 **현재 복사 중인 대상 경로**, 있으면 **빈 줄**. `-v`가 있으면 바로
    윗줄이 이미 파일을 알려주므로 중복이고, 대신 빈 줄이 로그 영역과 footer를 갈라준다.
  - **2행** — 진행바.

> **왜 항상 2줄인가.** 모드에 따라 높이가 달라지면 지우는 줄 수·높이 불변식·커서 이동이 전부
> 두 갈래가 된다. 높이를 고정하면 코드 경로가 하나고, `-v`를 준 쪽이 잃는 건 터미널 한 줄이다.
> 그 한 줄은 낭비가 아니라 **2영역 모델을 화면에 실제로 보이게** 하는 구분선 역할을 한다.

렌더링은 sole-writer 방식이다: `cprog`가 유일하게 터미널에 쓴다. 새 로그를 쓰기 전과 종료
전에 footer를 지웠다가 다시 그린다(erase-redraw). 이렇게 하면 두 영역이 서로를 깨뜨리지
않는다. footer 높이는 `min_log_rows`(기본 2)만큼 로그 영역을 항상 남긴다.

## 핵심 동작: 빠른 파일 vs 느린 파일

이게 자연스럽게 갈린다:

- **작은 파일이 많을 때** → `-v` 줄이 위에서 **빠르게 스크롤**. footer(바) 없음. "빠르게
  진행 중"이 스크롤 속도로 보인다.
- **큰 파일 하나** → 스크롤이 멈추고(그 `-v` 줄 하나), 100ms 넘으면 **footer에 바 등장**.
  끝나면 바 사라지고 다음으로.

## 예제 1 — 느린 파일 진행 중 (footer)

```
  'a.iso' -> '/mnt/backup/a.iso'                       ← cp의 -v 줄(로그 영역)
  ████████░░░░  62.34 %  0.9/1.4 GiB  (142 MiB/s)  ⏳ 00:05   ← footer
```

footer의 바 행(2행째)은 필드가 왼→오로 `bar · percent · size · (rate) · eta` 순이다:
- **bar** — 채움 비율. 폭은 **양자화**된다(100의 약수 `10/20/50/100`칸 중 들어가는 최대). 각
  칸이 딱 떨어지는 %(10/5/2/1%)라 정렬이 깔끔하고, 넓은 터미널일수록 해상도가 올라가며,
  뒤 필드 자릿수가 바뀌어도 바 길이가 안 흔들린다. 채움은 `█`/`░`이고, **모든 칸이 동일하게
  내림(floor)**으로 차므로 바가 완전히 차는 건 **진짜 100%일 때뿐**이다(percent의 내림과 같은
  "가짜 100 방지"). 10칸도 못 넣으면 바를 버린다.
- **percent** — 현재 파일 %(`stat(dst)/stat(src)`). **소수점 2자리**(대용량 진행 체감), 반올림
  아닌 **내림**(가짜 100 방지), **`100.00 %` 폭으로 우측정렬**(뒤 필드가 안 밀림).
- **size** — `복사된/전체` 용량. 단위는 **전체 크기에 맞춰 자동**(B/KiB/MiB/GiB/TiB), 예:
  `0.9/1.4 GiB`. 전체를 모르면(원본이 특수파일 등) 복사된 양만 표시.
- **rate** — 최근 구간 평균 속도, **괄호로 묶어** 부가정보임을 표시: `(142 MiB/s)`.
- **eta** — 현재 파일 남은분 / rate (`--:--`면 아직 모름).

## footer 1행 — 파일 이름

`-v`가 없으면 이 줄이 **유일하게 파일을 알려주는 곳**이다. 화면 어디에도 `-v` 줄이 없기 때문이다.

### 앞에서 자른다

경로에서 의미 있는 부분은 **뒤쪽**이므로, 폭이 모자라면 앞을 버리고 말줄임표를 붙인다:

```
/mnt/data/backup/archives/dataset.tar.zst
                  ↓ 폭이 모자라면
…/archives/dataset.tar.zst
```

- 말줄임표는 `…`(1칸), UTF-8이 아니면 `...`(3칸) — 바 글리프·`⏳`와 같은 `Style.unicode` 폴백.
- 자르는 기준은 바이트가 아니라 **표시폭**이다. 한글·CJK는 한 글자가 2칸이므로 바이트로 자르면
  넘친다. 문자 경계에서 멈춘다.

### 원본이 아니라 **대상** 경로다

진행률이 대상 크기로 계산되므로, 화면의 두 정보(이름·진행)가 **같은 파일**을 가리켜야 한다.
대상 경로는 `/proc`에서 이미 얻어 `stat`하고 있어 추가 비용도 없다.

### 제어문자는 자르기 **전에** 없앤다

`/proc/<pid>/fd` readlink가 준 경로에는 개행이 들어갈 수 있다(리눅스에서 합법). 그대로 그리면
footer가 한 줄을 넘어가 화면이 깨진다. 개행·제어문자를 먼저 제거하고, 그 다음에 폭을 맞춘다.

> 이 두 가지(폭 초과·제어문자)는 **미관 문제가 아니라 정확성 문제**다. footer가 2줄이 되면서
> 지우는 경로가 커서를 위로 한 줄 올리는데, 어느 줄이든 폭을 넘겨 터미널이 접어버리면 그 계산이
> 어긋나 화면이 망가진다. 각 줄은 **반드시** 폭 안에 들어와야 한다.

> ⚠️ %/size/rate/eta는 **현재 파일 하나** 기준이다. 전체 작업 %/ETA는 없다(총량 미계산).

## 예제 2 — 초기 (rate/eta 아직 모름)

충분한 샘플이 쌓이기 전엔 엉뚱한 숫자 대신 미지수로 표시한다.

```
  █░░░░░░░░░░░   4.30 %  0.1/1.4 GiB  (-- MiB/s)  ⏳ --:--
```

## 예제 3 — 빠른 소파일 구간 (footer 없음)

```
 'img001.jpg' -> 'backup/img001.jpg'
 'img002.jpg' -> 'backup/img002.jpg'
 'img003.jpg' -> 'backup/img003.jpg'
 'img004.jpg' -> 'backup/img004.jpg'      ← -v 줄이 빠르게 스크롤 = 활동 표시
```
바 없음. 각 파일이 100ms 안에 끝나므로 footer가 안 뜬다.

## 예제 4 — 완료 요약

**진행바가 한 번이라도 떴을 때만**(‑ 실제 복사를 감시했을 때) `cp`가 0으로 끝나면 footer를
지우고 **stderr**에 한 줄 남긴다(파이프 stdout 오염 방지). `--help`처럼 복사가 없던 실행엔
요약을 아예 안 낸다:

```
  ✓ done - 00:14 elapsed
```
> 파일 개수/총 바이트는 안 센다(전수 stat 회피). 그래서 요약은 **항상 `✓ done - T elapsed`로
> 최소한**이다. (단일 파일일 때 dst를 한 번 stat해 `✓ a.iso 2.10 GiB - 00:14 elapsed`처럼
> 크기를 붙일 수는 있겠지만, 지금은 구현하지 않았다.)

## 예제 5 — 실패 / 시그널

실패(비-0 종료) 시 footer를 지운다. `cp`의 에러는 이미 로그 영역에 있으므로 요약은 중립적으로
종료 코드와 elapsed만 표시(stderr):
```
 cp: 'a.iso' -> '...': No space left on device
  ✗ cp exited 1 - 00:03 elapsed
```
"failed"가 아니라 **`cp exited n`**으로 쓴다 — 비-0가 곧 완전 실패는 아니고(예: `-r` 없이
디렉터리 건너뜀), cprog는 이유를 판단하지 않는다. 왜 그랬는지는 위 `cp` 메시지가 말해준다.

**시그널**(Ctrl-C 등) 시엔 footer만 지우고 **요약 없음** — `cp`의 signaled-exit 의미론
보존이 우선.

## 예제 6 — 좁은 터미널 (단계적 축약)

폭이 줄면 오른쪽부터 필드를 버린다(줄바꿈 없음). percent가 가장 오래 남는다. 바는 양자화
폭(`50→20→10`)으로 줄다가, 10칸도 못 넣으면 버려진다:

```
80: ████████████████████░░░░░░░░░░  62.34 %  0.9/1.4 GiB  (142 MiB/s)  ⏳ 00:05
56: ████████████░░░░░░░░  62.34 %  0.9/1.4 GiB  (142 MiB/s)      ← eta 버림
44: ████████████░░░░░░░░  62.34 %  0.9/1.4 GiB                   ← rate 버림
30: ██████░░░░  62.34 %  0.9/1.4 GiB                             ← (바 10칸)
18: ██████░░░░  62.34 %                                          ← size 버림
 9:  62.34 %                                                     ← bar 버림
```
**버리는 순서(먼저→나중):** `eta → rate → size → bar → percent`.
percent가 가장 정보량이 커서 최후까지 남긴다. size가 rate보다 오래 남는 건 "얼마 중 얼마"가
핵심 정보라서다.

## 예제 7 — Passthrough (UI 없음)

리다이렉트/비-TTY/CI/비-리눅스에서는 `cprog`가 자기 출력을 **하나도** 안 낸다.
`cprog a b > log`는 `cp a b > log`와 **바이트 단위로 동일**.

## 색/글리프 정책

- 색은 stdout이 TTY이고 `TERM`/`NO_COLOR`이 허용할 때만.
  - 바 채움: green
  - 요약 `✓` green, `✗` red
  - (eta dim은 미구현 — 레이아웃 폭 계산이 SGR을 세지 않도록 하려면 폭 측정 후 별도 색칠이
    필요해 보류. 바/요약 색은 폭 측정을 안 건드려 적용됨.)
- UTF-8 블록 글리프가 안 되면 ASCII 폴백: `[######----]`.
- **커서 숨김:** footer가 떠 있는 동안 커서를 숨긴다(`\x1b[?25l`) — 안 그러면 바 끝에서
  깜빡인다. 종료 시(모든 경로, `FooterGuard::Drop`) footer를 지운 뒤 커서를 복원한다(`\x1b[?25h`).
- 깜빡임 없음, alternate screen 없음, 마우스 없음 — footer 한 줄이 전부.

## 렌더러가 지켜야 할 불변식 (테스트 대상)

1. footer는 로그를 쓰기 전과 종료 전에 **항상** 지워진다(모든 경로: 정상/에러/시그널/panic).
2. footer 높이(**2행**)는 `terminal_height − min_log_rows`를 넘지 않는다 → `rows ≥ 4`일 때만
   나타난다.
3. passthrough 모드 출력은 `cp`와 바이트 동일.
4. 렌더/IO 실패가 `cp` exit code를 **절대** 바꾸지 않는다(best-effort 그리기).
5. 현재 파일 크기를 모르면 가짜 100%가 아니라 indeterminate로 표시.
6. 바 폭은 양자화(`10/20/50/100`)돼 뒤 필드 텍스트 폭이 바뀌어도 흔들리지 않는다.
7. footer의 **어느 줄도 터미널 폭을 넘지 않는다.** 파일명 줄은 제어문자를 제거한 뒤 표시폭
   기준으로 앞에서 자른다. 넘치면 터미널이 줄을 접어 2행 지우기의 커서 이동이 어긋난다.
8. percent는 `100.00 %` 폭으로 우측정렬(고정폭)돼, 값이 커져도 뒤 필드가 밀리지 않는다.
9. 커서는 footer 활성 중 숨겨지고(모든 종료 경로에서) 복원된다.
10. `-v`를 주지 않았으면 **로그를 한 바이트도 중계하지 않는다**(‑ cp의 에러는 예외). `-v`를 줬으면
    그대로 중계한다.
11. **개행으로 끝나지 않은 로그 줄이 화면에 남아 있는 동안에는 footer를 그리지 않는다.**
    footer는 `\r`로 그 줄 맨 앞으로 돌아가 덮어쓰고, 다음 erase가 줄을 통째로 지우므로,
    부분 줄 위에 footer를 그리면 **그 로그가 화면에서 사라진다.** 다음 개행이 도착하면 다시 그린다.

### 왜 11번이 필요한가 (실제 사례)

`cp`의 에러 한 줄은 glibc `error()` 때문에 **write 4회**로 쪼개져 온다
(`"cp: "` / `"cannot …"` / `": 이유"` / `"\n"`). relay는 (의도적으로) 개행을 기다리지 않고 즉시
흘리므로 조각마다 `write_log`가 한 번씩 돌고, 그때마다 footer가 그 줄을 덮은 뒤 다음 erase가
지운다. 결과적으로 **개행을 품은 마지막 조각만 살아남아** 화면엔 `: No space left on device`처럼
파일명도 동작명도 없는 파편만 남는다. 판정 기준은 "무엇을 읽었나"가 아니라 **"터미널에 실제로
써넣은 마지막 바이트가 개행이었나"** 다 — stdout과 stderr가 한 화면에서 합쳐지기 때문에
스트림별 상태로는 알 수 없다.
