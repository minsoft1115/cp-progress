# Overview (개요)

## 프로젝트 목표

`cprog`는 `cp`의 대체품이 아니다. **리눅스 대화형 터미널에서만** per-file 진행바를
얹어주고, 그 외 모든 곳에서는 `cp`와 바이트 단위로 동일하게 동작하는 **얇은 래퍼**다.

`cprog`는 외부 진행률 도구도, hidden PTY도, 화면 스크래핑도 쓰지 않는다. 진행은 `cp` 자신의
`-v` 출력(타이밍)과 커널의 `/proc`/`stat`(현재 파일 크기)만으로 파악한다.

## 확정 컨셉 (핵심)

1. **진짜 복사는 `cp`가 한다.** 권한·sparse·reflink·xattr·ACL 등 모든 의미론은 안 건드린다.
   `cp`의 **exit code와 시그널이 언제나 최종 권위**다.
2. **Managed 모드**(대화형 TTY + 리눅스 + 안전):
   - `-v`를 주입하고(사용자가 이미 줬으면 그대로), **`stdbuf -oL`로 감싸** `cp`의
     stdout/stderr를 **캡처**한다. (`stdbuf`가 없으면 `-v`가 실시간으로 안 흐르므로 →
     passthrough로 폴백. [`capture-and-verbose.md`](./capture-and-verbose.md) 참조.)
   - 캡처한 출력은 **사용자가 `-v`를 실제로 줬을 때만** 위쪽 로그 영역으로 흘려준다. 안 줬으면
     타이밍 판정에만 쓰고 버린다 — 요청하지 않은 출력을 쏟지 않는다(‑ `cp`의 에러는 항상 중계).
   - 한 파일이 임계(기본 100ms)보다 오래 걸릴 때만, 하단 **footer 2줄**을 그린다 — 1행은 대상
     경로(‑ `-v`를 줬으면 빈 줄), 2행은 진행바.
   - 바 데이터는 `/proc/<pid>/fd`로 현재 파일 경로를 얻어 `stat().st_size`로 계산한다.
   - 파일이 끝나면 footer는 사라진다.
3. **Passthrough 모드**(비-TTY/파이프/CI/비-리눅스/`-i`): 스트림 inherit, `-v`·캡처·footer
   전부 없음 → **`cp`와 바이트 동일.**

## `-v`의 역할 (중요 — 파싱하지 않는다)

`cprog`는 파일 개수를 세지 않는다. 따라서 `'src' -> 'dst'` 줄의 **내용을 파싱하지 않는다.**
`-v`는 두 가지로만 쓴다:

- **활동 표시:** 스크롤되는 `-v` 줄이 "빠르게 복사 중"이라는 신호다. (단 이게 실시간이려면
  `cp`를 `stdbuf -oL`로 라인버퍼 강제해야 한다 — 위 참조.)
- **타이밍 펄스:** 새 줄이 하나 뜸 = "새 항목 시작". 다음 줄이 100ms 안에 안 오면 현재
  파일이 "느린 파일" → 바를 그린다.

바에 필요한 실제 파일 경로는 `-v` 텍스트가 아니라 **`/proc/<pid>/fd` readlink**에서
얻는다. 따라서 quote/`->`/unquote 파싱이 없고, **파일명에 개행(`\n`)이 있어도 무관**하다.

## 설계 요지 (무엇을 쓰고 안 쓰나)

- **안 쓰는 것:** 외부 진행률 도구, hidden PTY, VT100 화면 파서, 원본 트리 walk, 파일 카운트.
  (진행률 화면 스크래핑·화면 에뮬레이션 같은 복잡한 계층이 아예 없다.)
- **쓰는 것(단순):** `-v` 타이밍(느린 파일 감지) + `/proc`/`stat`(현재 파일 진행) +
  sole-writer footer + RAII 화면복구(`FooterGuard`) + SIGWINCH(+폴백) + `Fatal`
  타입 + stderr 요약 + 시그널 보존 종료.

## 범위 (Scope)

- 인자 pass-through(interactive 감지 정도의 최소 검사)
- managed vs passthrough 선택
- `-v` 주입/캡처/중계(sole-writer)
- 느린 파일 감지(‑v 타이밍) + `/proc`+`stat` per-file 바
- footer 정리(모든 종료 경로), 시그널 보존 종료

## Non-Goals (안 하는 것)

- `cp` 또는 복사 의미론 재구현
- **파일 개수 세기**(모든 항목을 `stat`해야 해서 대량 소파일에서 성능 저하 → 안 함)
- **전체 작업 %/ETA**(전체를 알려면 원본 트리를 walk해야 함 = cp 복제 → 안 함).
  per-file %/ETA는 함(현재 파일 하나만 stat).
- 비-리눅스 지원(footer는 리눅스 전용; 그 외엔 passthrough로 동작)
- reflink/CoW·희소파일에서의 바이트 정확 진행(튀거나 건너뜀 — 한계로 명시)
